## 1. Feedback themes → product changes

### Theme: On-chain operations felt like a black box
- **Problem:** During wallet/contract calls users could not tell whether anything was happening; failures were silent.
- **Example feedback:** Harness-batch rows repeatedly mention loading indicators, status clarity, pending vs. success states. *(unverified source)*
- **Product change:** Real-time transaction status machine — `simulating / awaiting_signature / submitting / pending (attempt n/15) / success / timeout / failed` surfaced in the UI for every on-chain call.
- **Commit:** `57e442c` (2026-07-30) — **predates all collected feedback**, so this is *alignment*, not causation.
- **Status:** Implemented.

### Theme: Registration errors were confusing / server-error-looking
- **Problem:** Registering an already-known wallet returned an opaque failure.
- **Product change:** Clean `409 Conflict` handling with a dedicated "Already Registered" panel linking to Dashboard / Get Verified; backend returns 409, never 500.
- **Commit:** `1a0a2e4` (2026-08-01).
- **Status:** Implemented.

### Theme: Navigation / entry points unclear
- **Problem:** Testers did not know where to start or where to give feedback.
- **Product change:** Register / Users / Feedback added to navigation; floating feedback widget; `/technical-preview` page with a structured "What to test" guide.
- **Commits:** `acb2c13`, `5434c3c` (2026-07-23), `36b9ec7` (2026-07-30).
- **Status:** Implemented.

### Theme: Reliability of error tracking & follow-up
- **Change:** Migrated Sentry → GlitchTip for both frontend and backend so feedback events and production errors land in one place.
- **Commit:** `fdb9489` (2026-08-20).
- **Status:** Implemented.

## 3. What we can honestly say

- The product iterated substantially between July 23 and August 25, 2026 across status visibility, registration UX, navigation, and error handling.
- Genuine external feedback is currently **thin (≈1 corroborated response)**; the larger sheet volume is disclosed harness output and is not used as adoption evidence.
- Future feedback will be collected via the same public form and the in-app widget, with responses timestamped and reviewable.
